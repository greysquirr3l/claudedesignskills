    API 04 — Threading

    Web Workers

    Offload heavy computation to a background thread. The main thread — and the UI — remain responsive. Communication is message-based via postMessage. No shared memory by default; pass ArrayBuffer via transfer for zero-copy performance.

    ✅ Run 50 million iterations off-thread — UI stays alive

    Main Thread UI

    This counter keeps ticking even while the worker runs

    0

    ⚙️ Worker Thread

    Idle — press Run to start
    The pattern
    // main.js const worker = new Worker("worker.js"); worker.postMessage({ iterations: 50_000_000 }); worker.onmessage = (e) => console.log("Done:", e.data.result); // worker.js — separate file, separate thread self.onmessage = ({ data }) => { let sum = 0; for (let i = 0; i < data.iterations; i++) sum += i; self.postMessage({ result: sum }); };
    API 05 — Visibility

    Intersection Observer

    Replaces scroll event listeners — which fire on every pixel of movement — with an async, browser-optimized callback that fires only when an element enters or leaves the viewport (or a custom root). Zero janks, zero layout thrash.

    ✅ Scroll down — cards animate in as they enter the viewport
    The pattern
    const observer = new IntersectionObserver( (entries) => { entries.forEach((entry) => { if (entry.isIntersecting) { entry.target.classList.add("visible"); observer.unobserve(entry.target); // fire once } }); }, { threshold: 0.15 } // 15% visible triggers callback ); document.querySelectorAll(".io-card").forEach((el) => observer.observe(el) );
    API 06 — UX Shortcut

    Clipboard API

    A single line replaces the old execCommand('copy') hack. Promise-based and permissions-aware. Writing to the clipboard is allowed in response to a user gesture; reading requires an explicit permission grant.

    ✅ Copy preprogrammed text — then read it back
    navigator.clipboard.writeText()
    ✓ Copied
    Clipboard contents will appear here…
    The pattern
    // Write — allowed on user gesture (button click, keydown) await navigator.clipboard.writeText("Copied text"); // Read — prompts for clipboard-read permission const text = await navigator.clipboard.readText(); console.log(text); // Rich content (HTML, images) via write() await navigator.clipboard.write([ new ClipboardItem({ "text/html": new Blob(["<b>Bold</b>"], { type: "text/html" }) }) ]);
    API 07 — Immersion

    Fullscreen API

    Any DOM element can go fullscreen — not just the document. Style the fullscreen state with the :fullscreen pseudo-class. Essential for media players, data dashboards, and presentation modes.

    This card becomes the entire screen

    Esc or the button above exits fullscreen mode

    The pattern
    const el = document.getElementById("my-player"); // Enter await el.requestFullscreen(); // Exit await document.exitFullscreen(); // Detect state change (Esc key also fires this) document.addEventListener("fullscreenchange", () => { const isFullscreen = Boolean(document.fullscreenElement); console.log(isFullscreen); }); /* CSS — style the fullscreen state */ #my-player:fullscreen { background: black; }
    API 08 — Navigation

    History API

    Client-side URL changes without a page reload. The foundation of every SPA router. pushState adds an entry; replaceState mutates the current one. The popstate event fires when the user navigates with the browser's back/forward buttons.

    ✅ Click the nav tabs — watch the fake URL bar update without a reload
    localhost:3000 /home
    Home Welcome! You are on the home view.
    The pattern
    // Push a new URL without navigating (works on http:// and file://) history.pushState({ view: "about" }, "", "?page=about"); // relative = safe // Or use hash routing — zero restrictions, works everywhere location.hash = "about"; // → #about // Handle both back/forward and hash changes window.addEventListener("hashchange", () => { const view = location.hash.slice(1) || "home"; renderView(view); }); // pushState with relative URL also works on file:// history.pushState(null, "", "./home"); // relative path ✅

    12 — Broadcast Channel

    BroadcastChannel API

    Send messages between all pages from the same origin — tabs, windows, iframes, workers — with zero infrastructure. Classic use case: broadcasting a logout across all open tabs.

    ✅ Two in-page channel endpoints (simulating two tabs)
    Tab A
    Listening…
    Tab B
    Listening…
    The pattern
    // Same channel name = same broadcast group (same origin only) const ch = new BroadcastChannel("auth"); // Receive ch.onmessage = (e) => { if (e.data === "logout") redirectToLogin(); }; // Send (fires in every other page on the same channel) ch.postMessage("logout"); // Always close when done ch.close();
