Readability

Line Length: The 65ch Rule

Ideal body text: 50–75 characters per line. On a wide monitor, full-width text can run 150+ characters — the eye travels too far and loses its place. max-width: 65ch is the single-property fix.

❌ Full width — exhausting to track

This paragraph stretches all the way to the edge of its container. On a large monitor a single line can exceed 120 characters. The reader's eye makes an enormous journey back to the start of the next line, burning focus before understanding even begins.

✅ 65ch max — comfortable rhythm

This paragraph is constrained to 65 characters wide. Each line completes in a comfortable arc. The eye snaps back cleanly to start the next line without losing its place in the text.

Color System — 2026

OKLCH: Perceptually Uniform Color

OKLCH is the recommended color space for 2025–2026. Unlike HSL, its lightness channel matches human perception — so the same L value looks equally bright across all hues. Gradients have no muddy gray midpoints. Relative colors enable systematic darkening/lightening without hardcoding new hex values. Baseline widely available.

Visual Depth — 2026

Glassmorphism

Dominant SaaS aesthetic: frosted-glass panels create depth without consuming space. Requires backdrop-filter: blur() on a layer that has something colorful behind it. Remember: contrast degrades — bump typography weight or darken text on light-behind backgrounds.

Without Glass

Plain dark background. No depth relationship to content behind the card.

With Glassmorphism

The gradient behind bleeds through, frosted. The panel feels elevated without a drop shadow.

Layered

Multiple glass panels can stack. Each one compounds the depth effect.

backdrop-filter: blur(18px) saturate(180%) + background: rgba(255,255,255,0.07) + border: 1px solid rgba(255,255,255,0.18). Must have a colorful or image-based background behind the element.

CSS Selectors — 2026

The :has() Parent Selector

The most used and most loved CSS feature in the State of CSS 2025 survey. Enables parent selection and conditional styling that previously required JavaScript. Baseline widely available.

Form group border turns coral when input is invalid — type letters in the email field

.form-group:has(:invalid) { border-color: coral; }

Entire card highlights when its inner button receives keyboard focus — Tab to the button

Card content. The whole card responds to focus inside it, not just the button.

.card:has(button:focus-visible) { border-color: cyan; }

Typography Precision — 2025+

text-box: Perfect Vertical Centering

A font's content box is sized by its internal ascent/descent metrics, not by the cap height and baseline where Latin glyphs actually live. This makes text look optically high even when it is mathematically centered. text-box: trim-both cap alphabetic removes the phantom whitespace. Chrome 128+, Safari 18.2+.

❌ Default — text sits visually high inside the box

Font metrics push cap height above the vertical midpoint. Looks off on short buttons and icon–label pairs.

✅ text-box: trim-both cap alphabetic — optically exact

Cap height aligns to the true centre. No hacks, no magic numbers, no padding-top: 3px tweaks.

Animation — 2025+

sibling-index() Staggered Animations

Previously, staggered list animations required counting DOM elements and hardcoding :nth-child(n) { animation-delay: Xms } for every item. The new sibling-index() function returns each element's position automatically, making the delay formula one line of CSS regardless of list length. Chrome 137+.

  • Design token layer (primitives)
  • Semantic alias layer (meaning)
  • Component token layer (scoped)
  • Utility override layer (last resort)
  • Theme variant layer (dark / light)

animation-delay: calc(0.08s * (sibling-index() - 1)) — delay scales automatically. Add or remove list items; zero CSS changes needed.

Before @starting-style, animating an element as it appears required JavaScript to add a class one frame after insertion. Now you declare entry state in CSS alone. Loading UX — 2026

Skeleton Screens vs Spinners

A spinner tells the user they are waiting. A skeleton screen shows them what they are waiting for, matching the layout that will appear. Perceived load time is shorter because the user's eye has already mapped the structure. The shimmer is pure CSS — a background-position keyframe animation.

CSS :has() — 2025+

Dark / Light Mode Toggle — Zero JavaScript

A hidden <input type="checkbox"> drives the entire theme switch. :has(.theme-cb:checked) on the wrapper container rewrites scoped CSS custom properties — no JS event listeners, no classList.toggle, no data-theme attribute mutations. The transition on every property makes the flip feel polished. Baseline widely available (Chrome 121+, Firefox 121+, Safari 17.2+).

Design token card
All colours, shadows, and borders reference scoped --td-* variables. Flipping the checkbox rewrites every token at once — one selector, zero JS.
How it works
.wrapper { --td-bg: dark; }
.wrapper:has(input:checked) { --td-bg: light; }

The `:has()` selector targets an ancestor based on a descendant's state. Previously impossible without JS.

Scale this up by scoping to html:has(#toggle:checked) to switch the entire page theme from a single checkbox anywhere in the DOM.

Media — 2026

Video: Inline & Background Patterns

<video> is a replaced element like <img> — it obeys object-fit, aspect-ratio, and border-radius. The two main patterns are inline (content video with controls and captions) and background (ambient, muted, decorative). They have opposite attribute requirements.

❌ Bad — fixed pixel dimensions, no aspect-ratio
<video width="640" height="360"> — breaks on small screens, overflows containers, requires JS resize hacks
width="640" height="360" no object-fit no <track>
✅ Good — aspect-ratio wrapper + semantic attributes
Caption track renders here — always provide a <track>
preload="none" controls playsinline poster="…" <track kind="captions"> aspect-ratio: 16/9
✅ Good — background video hero (muted, autoplay, aria-hidden)

Background Video Hero

Text sits on a scrim — legible at any contrast level

autoplay muted loop playsinline aria-hidden="true" tabindex="-1" object-fit: cover prefers-reduced-motion fallback no controls no <track> needed
Inline video rules
  • • Wrap in aspect-ratio: 16/9 container — never set px dimensions
  • • Always include a poster image (prevents layout shift)
  • • preload="none" — don't download video until user initiates
  • • Add <track kind="captions"> — WCAG 2.1 AA requires captions
  • • playsinline prevents iOS full-screen hijack
  • • Serve WebM first, MP4 as fallback (<source> order matters)
Background video rules
  • • Always muted — browsers block autoplay with audio
  • • aria-hidden="true" + tabindex="-1" — decorative, not content
  • • Always overlay a scrim (linear-gradient) for text legibility
  • • @media (prefers-reduced-motion: reduce) — hide video, show static fallback
  • • will-change: transform promotes to GPU compositor layer
  • • Keep clips short (≤ 10s loop) and compressed — aim for < 2 MB

Source order for <source>: WebM (AV1 or VP9) first — smaller file, better quality. MP4 (H.264) as the universal fallback. Never use autoplay without muted; browsers will silently block it.

Forms — HTML Fundamentals

Input Types Worth Knowing

Skipping the obvious (text, password, email, number). These are the input types that eliminate JS libraries, improve mobile UX, and are easy to forget exist. All use accent-color to pick up your brand colour automatically.

Native pickers — zero JS

type="date" Native date picker. min/max constrain the range. Replaces every date-picker library for 90% of use cases.
type="time" Native time picker. Eliminates AM/PM dropdowns. min/max restrict bookable hours.
type="datetime-local" Date + time in a single field. Ideal for event bookings and scheduling forms.
type="month" Month + year only. Perfect for credit card expiry or monthly billing cycles.
type="week" Week-of-year selector. Niche, but eliminates bespoke week pickers in timesheet apps.
type="color"
Native OS colour picker. No library needed for theme pickers, annotation tools, or simple config UIs.
type="range"
50
Slider for bounded values. accent-color styles the thumb and track. Pair with an oninput display for feedback.
type="search" Adds a clear (✕) button in most browsers. Semantically correct — assistive tech announces it as a search field.

Mobile keyboard optimisation

type="tel" Triggers numeric keypad on iOS/Android. Does not validate format — combine with pattern if you need that.
type="url" Shows .com and / keys on mobile. Browser validates URL format on submit.
inputmode="numeric" inputmode controls the on-screen keyboard without changing validation semantics. Use for PINs, OTPs, codes.
capture="environment" On mobile, opens the rear camera directly instead of the file browser. capture="user" for selfie/front camera.

Power attributes

list + <datalist> — zero-JS autocomplete Free-text plus suggestions, no JS. The list attribute links to a <datalist> by ID. Works on all modern browsers.
pattern — regex validation without JS pattern runs a regex against the value on submit. Always combine with title — it becomes the validation tooltip. Example: booking reference format.
autocomplete — stop frustrating users Use autocomplete tokens (email, given-name, street-address, etc.) so password managers and browsers fill forms correctly. Never set autocomplete="off" on login forms — it breaks password managers.
minlength / maxlength + required required blocks empty submission. minlength/maxlength constrain character count. The browser validates all three — no JS needed for these common constraints.

Left out intentionally: text, password, email, number, checkbox, radio, hidden, submit, reset, image — well documented everywhere, and <button type="submit"> is preferred over type="submit" and type="button" inputs for flexibility.
