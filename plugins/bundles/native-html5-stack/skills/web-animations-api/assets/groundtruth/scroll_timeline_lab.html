CSS scroll-timeline Lab

Scroll-driven animations arrived natively in 2023. Link any @keyframes animation to scroll position using animation-timeline: scroll() for container progress, or animation-timeline: view() to animate elements as they enter the viewport — no JavaScript, no IntersectionObserver, no requestAnimationFrame.

Browser support (2026): Chrome 115+, Edge 115+, Firefox 127+, Safari 18+. Guard with @supports (animation-timeline: scroll()) for older engines. All seven demos below run natively in any of those.

Demo 01 — scroll progress

Reading progress bar scroll-timeline-name

scroll-timeline-name gives a scrollable container an identity. The sticky gradient bar inside reads that identity via animation-timeline: --reader and grows from 0 → 100% with a plain scaleX keyframe. No event listeners, no main-thread work. (Scroll the text ↓)

The case for scroll-driven animations

Before animation-timeline, every scroll-linked effect required JavaScript — a scroll event listener, throttling with requestAnimationFrame, manual progress calculation, and DOM updates on every tick. A reading-progress bar was 30+ lines of JS that ran on the main thread and competed with everything else the browser was doing.

The new model: scroll replaces time

Now you assign a scroll container a name — scroll-timeline-name: --reader — and point any animation at it: animation-timeline: --reader. The browser wires them together on the compositor thread. The scroll position becomes the clock hand; the keyframe percentage becomes the scroll percentage.

Anonymous timelines

For the simplest cases you don't even need a name. animation-timeline: scroll() automatically uses the nearest scrollable ancestor. animation-timeline: view() tracks how much of the element is visible within that ancestor — the foundation of every scroll-reveal animation.

Named timelines and timeline-scope

scroll-timeline-name + timeline-scope on a common ancestor lets a scrollable element share its progress with elements that live elsewhere in the DOM tree — even siblings or cousins. This is what powers the horizontal-scroll gauge demo and the multi-axis 3D experiments from the CSS-Tricks article.

animation-range

By default the animation covers the full scroll range. Use animation-range: entry 0% entry 60% to fire only as the element enters the viewport, or contain to fire only while it's fully visible. The range keywords — entry, exit, contain, cover — give you surgical control over exactly which slice of scroll drives which slice of the animation.

↕ named scroll-timeline on the container
.container {
  scroll-timeline-name: --reader;
  scroll-timeline-axis: block;
  overflow-y: scroll;
}
.bar {
  position: sticky; top: 0;
  transform-origin: left;
  animation: fill linear both;
  animation-timeline: --reader;
}
◈ keyframe + scaleX trick
@keyframes fill {
  from { transform: scaleX(0) }
  to   { transform: scaleX(1) }
}
/* animation-fill-mode: both (via
   the "both" shorthand keyword)
   holds the 0% state before the
   scroll starts and 100% after */

Demo 03 — multi-layer scroll

CSS parallax named timeline + layer depth

One named scroll timeline drives three layers simultaneously — each with a different translateY endpoint. Because each layer is position:absolute, a positive translateY counteracts the viewport moving up, making it appear to move more slowly. Stars barely drift. The ground nearly keeps pace. Depth is pure arithmetic in @keyframes. (Scroll ↓)

Demo 07 — progress tracker

Step progress per-node view() activation

Each step node activates — border glow, colour shift, background tint — as it enters the visible area via animation-timeline: view(). The connector line below each node fills with a separate scaleY animation on the same timeline, with a slightly later animation-range so the fill trails the node activation. No scroll event. No JavaScript. (Scroll ↓)

1
Define the scroll container
Any element with overflow: scroll or auto can source a scroll timeline. The browser tracks its scroll position automatically.
overflow: scroll
2
Name it (optional)
Assign a scroll-timeline-name if you need to target the timeline from outside the container, or to share it across elements with timeline-scope. Skip it for view() — it auto-discovers its nearest scroll ancestor.
scroll-timeline-name
3
Write a normal @keyframes
Scroll timelines consume any existing keyframe animation unchanged. The only conceptual shift is that scroll position drives the progress percentage instead of elapsed time.
@keyframes
4
Set animation-timeline
Point the animation at scroll(), view(), or a named timeline. Add animation-fill-mode: both to hold the start and end states.
animation-timeline fill-mode: both
5
Tune with animation-range
Use animation-range to control which slice of scroll drives the animation. Keywords: entry, exit, contain, cover — plus arbitrary percentages.
animation-range

Demo 08 — @property + scroll

Palette rotation @property --hue + scroll()

@property registers --page-hue as an animatable <angle>. A single scroll() keyframe drives it from 200deg → 560deg (a full lap around the OKLCH wheel). Every colour on the screen is expressed as oklch(… var(--page-hue)), so the entire palette rotates in lockstep as you scroll — title, badges, swatches, body text. One keyframe replaces a whole theme-switching system. (Scroll ↓)

Scroll to rotate
Every colour here is expressed as oklch(L C var(--page-hue)). The @property declaration makes the custom property animatable as a real CSS angle, so the browser can interpolate it through the colour wheel continuously.
@property scroll() oklch
This is the same technique as the CSS-Tricks multi-axis 3D model — register animatable custom properties with @property, drive them with scroll timelines, and let the rest of the CSS inherit them. One scroll source can mutate an arbitrary number of derived values simultaneously.
↑ scroll to see the full hue lap ↑
↕ register + animate the custom property
@property --page-hue {
  syntax: "<angle>";
  inherits: true;    /* flows to children */
  initial-value: 200deg;
}
.page {
  animation: hue-spin linear both;
  animation-timeline: scroll();
}
@keyframes hue-spin {
  from{ --page-hue: 200deg }
  to  { --page-hue: 560deg }
}
◈ all colours inherit the hue
h1    { color: oklch(0.88 0.18 var(--page-hue)) }
.badge{ background: oklch(0.55 0.2
         var(--page-hue) / 0.15) }
p     { color: oklch(0.74 0.06 var(--page-hue)) }
/* Offset swatches with + N deg:
   swatch:nth-child(2) uses
   calc(var(--page-hue) + 40deg) */

Demo 09 — contain range

Scroll-peel stickers animation-range: contain → exit

Each card starts flat. As it exits the scroll container, a rotateX(-88deg) scaleY(0.15) keyframe makes it peel backwards off the screen — like a Post-it being lifted from a surface. The secret is animation-range: contain 0% exit 80%: the animation holds at 0% while the card is fully visible, then executes only during the exit phase. perspective on the parent makes the 3D rotation visible.   transform-origin: top center;
  animation: peel linear both;
  animation-timeline: view();

Demo 10 — custom property + scaleX

Warp-speed starfield scroll drives streak length

40 star spans each start as a 2-pixel dot. A named scroll timeline drives scaleX(1 → 22) + opacity fade. Scroll down: the stars stretch into light-speed trails. Scroll back up: they contract back to pinpoints. The depth illusion comes from varying each star's initial width and top/left position with inline styles. Zero canvas, zero JS. (Scroll ↓)

↕ scaleX driven by scroll progress

.star {

  transform-origin: left center;

  animation-timeline: --warp;

Scroll typewriter max-width: 0ch → 100%

Demo 12 — 3D preserve-3d

Card deck deal rotateY + translateX + view()

Each card starts rotated 72deg off-axis — invisible edge-on — and translates in from off-screen. As it enters the viewport, view() snaps it flat with a satisfying 3D swing. Odd and even cards swing from opposite sides (rotateY ±72deg) using two keyframes selected by :nth-child(odd). perspective on the scroll container provides the shared vanishing point. (Scroll ↓)

The core insight. Scroll-driven animations don't replace @keyframes — they replace the clock that drives them. Swap elapsed time for scroll position, and the same keyframe that fades in a modal now fades in a card as it enters the viewport. That single conceptual swap — combined with @property for animatable custom properties and timeline-scope for cross-DOM reach — unlocks palette rotation, warp-speed starfields, typewriters, 3D card decks, and peel effects. All pure CSS. All on the compositor thread.
